Wider MuseTalk blending did not fix the visible mouth patch: it removed lower-face detail. Sampled LatentSync frames preserved more coherent facial texture. The warm batch profile attributed 49.8 s to waiting for denoising workers, 8.0 s to conditioning, 7.6 s to decode/audio/face preparation and 0.15 s to collecting/pasting chunks. Decode/audio/face preparation is a mixed stage, not a measurement of CPU decode alone. Next allocation trial: separate coordination from denoising only if profiling shows workers starving. Avoid forcing all eight GPUs busy when communication adds more latency than useful work.

After moving avatar speech from GPU 5 to GPU 0, one real WebRTC run measured 1.17 s from end of speech to heard response, 1.11 s to motion, 25 FPS, 98 ms of audio after interruption and zero render fallbacks. Mixed-load tail latency still needs testing.

## Implemented quality safeguards

- API accepts validated LatentSync steps, guidance and seed overrides; fast routing and concurrency are independent from batch.
- Quality translation runs contextual revision, retains a draft/revision audit, and blocks synthesis on unresolved issues or number/terminology discrepancies. This uses the same model and is not independent validation.
- Final speech can use trailing source silence. The original “Good morning” clip had only 0.72 s of recognized speech but a 1.34 s available final slot. The repaired quality job completed in 34.2 s.
- Fast mode still failed a stochastic TTS timing trial after that repair. Four-take retry configuration was staged remotely, but activation and a repeat run could not be confirmed. Do not call this failure resolved.
- Subsequent local fixes preserve rejected translations for editing, give actionable duration errors, and explicitly reject incorrect speech after a rewrite. These final fixes are not yet deployed because server access was lost.
