# XE7740 deployment and measured validation

Date: 3 October 2026. This report supersedes earlier statements that GPU access is unavailable.

## Status

The local changes were deployed to `/home/user/xeon-video-translation` on XE7740 and iterated against the actual hardware. Native GPU codecs, translation, batch lip-sync and a real WebRTC voice/avatar round trip have executed successfully. This is a functional GPU deployment with measured improvements. It is **not yet a completed perceptual-quality or production-load qualification**.

The host has eight RTX PRO 6000 Blackwell Server Edition GPUs (SM120, about 96 GB each), driver 580.178.04 and CUDA 13.0 driver support. Unrelated Intel/agentic services remain running. The external CPU vLLM server was preserved; the video project now has its own GPU vLLM service.

Source remains uncommitted on base `025b01e777104a0dabbbd2b704a064b429cc27e0`; deployment manifests fingerprint the changed and untracked files. Do not identify this deployment by the base commit alone.

## Final GPU allocation

GPU 0: translation ASR/XTTS; GPU 1: shared project GPU LLM; GPU 2: dedicated avatar renderer and WebRTC hardware codecs; GPU 3: fast video renderer; GPUs 4/6/7: batch renderer; GPU 5: dedicated avatar ASR/XTTS. Speech models remain large-v3/XTTS for this trial; no ASR downgrade was used to obtain the latency figures. GPU 2 shares codec engines and avatar rendering intentionally. Reserving avatar speech capacity reduces the batch pool from four to three GPUs; this trades batch throughput for isolation of interactive responses. There is no dynamic borrowing scheduler.

Start with `docker compose -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.llm.yml -f docker-compose.avatar.yml up -d`. The host's preserved `.env` contains the exact assignments, including `AVATAR_BACKEND_GPU=5`, `AVATAR_MUSETALK_GPU=2`, `INGEST_GPU=2` and `LATENTSYNC_GPUS=4,6,7`. These differ from the generic layout-generator defaults.

## Measured baseline and improvements

The repeatable translation fixture is 52.067 seconds, combining a short looped portrait video and synthesized English narration, translated to Spanish. It is suitable for performance screening and weak evidence for natural conversation or identity quality.

Cold and warm observations are separated. These counts do not support p95 claims. Endpoint-to-heard starts at the received server endpoint event, not the physical end of user speech. First image change is a motion proxy, not a lip-sync score. A local client container does not validate browser/TURN/WAN behavior. Near-25 FPS alone does not certify continuous active video or audiovisual skew.

A GPU ASR consistency check against the final synthesized text found one spelling/accent difference (`video`/`vídeo`) in each of two 135–136-word outputs, with no detected omissions. This uses the same Whisper family as the pipeline and is not an independent quality judge. Native-speaker listening, voice identity and semantic review remain required.

## Defects found and fixed on the host

1. **GPU codec readiness failed on undersized probe frames.** NVENC needed larger dimensions on this GPU. Native round-trip probes now use 256×256 frames and execute the actual PyAV libraries.
2. **LLM requests went to CPU inference.** Added a project-owned GPU vLLM service on GPU 1, pinned to image digest and Qwen3-30B-A3B-Instruct-2507 revision. Added bounded model-availability checks to backend readiness.
3. **Batch failed on an unsupported FFmpeg option.** Replaced `-fps_mode passthrough` with compatible `-vsync 0` for the tested FFmpeg versions.
4. **Expensive convolution searches inflated startup.** ONNX Runtime uses HEURISTIC search, and cuDNN benchmarking defaults off. Both remain explicit experiment knobs.
5. **Face detection cache could collide.** Hash the complete input file. Disable detection cache for benchmark cohorts that should measure actual detector work.
6. **WebRTC high-resolution recordings crashed the ingest process.** Audio muxing could open the video codec at default dimensions before the first video frame arrived. A startup barrier now configures video dimensions before muxing starts. The same 1080×1920 recording completed after the fix.
7. **Recording delayed avatar interruption.** Encode/mux work now runs in a bounded single worker per recorder. Native work drains before file closure, even when the stop caller is cancelled. Regression tests cover delayed video startup, codec failures, bitrate reuse and cancellation.
8. **NVENC bitrate updates recreated the encoder.** Update bitrate in place; preserve encoder state and RTP timestamps unless dimensions change.
9. **OpenCV/NumPy compatibility was unstable.** LatentSync's headless OpenCV is pinned to 4.11.0.86 with NumPy 1.26.4.
10. **Cold avatar admission caused a 46-second first reply and video fallback.** Dedicated speech and rendering models now load and execute ASR, streaming TTS and rendering at startup; admission requires both to report completed inference warm-up. A first attempt that only loaded weights still took 15 seconds, so it was rejected as insufficient. Failed backend warm-up no longer reports success.
11. **Benchmark source metadata was incomplete in containers without Git.** The harness can consume host-collected source provenance. Release artifacts include image IDs, source hashes and a model-file manifest.

A duration-fitting failure remains in the evidence: one truncated six-second recording failed with `no shorter faithful translation produced`. Another completed after the recorder changes. That does not prove the fitting issue was solved. The pipeline preserves speech by refusing unsafe fitting; it needs more reliable duration-controlled synthesis and representative short-utterance testing before qualification.

## Experiments that actually ran

See `experiments/flashhead/` for scripts, pinned source/model revisions and raw results.

- **FlashHead Lite:** warm model chunks at 114–117 FPS, first 24-frame chunk 392 ms, peak PyTorch allocation 5.35 GB. Promising next avatar candidate. Face softness and identity/motion still require review; no production WebRTC adapter is claimed.
- **FlashHead Pro:** about 18 FPS eager and 21.8–21.9 FPS compiled on one GPU, below the 25 FPS goal. Compiled first chunk took 150 s. Retain as an experiment; two GPUs and optimized attention remain untested.
- **PyNvVideoCodec 2.2.3:** decoded/imported/resized 120 1080p frames through DLPack/CUDA in 0.419 s, about 286 FPS. This is an isolated compatibility probe, not a GPU-resident application pipeline or encode benchmark.
- **Tiny Silero VAD, current host I/O interface:** CPU median 0.119 ms versus CUDA 0.402 ms per 32 ms frame after warm-up. CPU remains the measured faster choice for this control operation. Heavy ASR, LLM, TTS, rendering and video codecs use the GPU. Host frame conversion, audio resampling, control logic and some legacy transforms still use CPU.

## Warm-up fixtures and artifact limits

The dedicated overlay requires `/models/avatar-warmup/speech.wav` (short English PCM16 mono speech, at most ten seconds) and `/models/avatar-warmup/portrait.png` (valid face). Override with `AVATAR_WARMUP_AUDIO_PATH` and `AVATAR_WARMUP_IMAGE_PATH`. The XE7740 model volume contains the tested fixtures. These are private test inputs, not bundled model weights. Missing inputs or failed inference keep avatar admission closed with HTTP 503 and Retry-After; restart the affected dedicated service after correcting the inputs.

Warm-up includes actual GPU ASR, streaming XTTS and MuseTalk inference, not merely importing libraries or loading weights. The restart probe observed repeated HTTP 503 responses, then admission after about 38 seconds once inference warm-up completed. Startup availability and conversational latency are reported separately.

Repeated tests reached the prior 10 GB account artifact quota. The XE7740 test-host limit is now 32 GB, with ample disk headroom; all previous outputs were preserved. The rejected HTTP 413 submission is retained as an operational failure. The benchmark harness now records HTTP submission failures instead of dropping them from the run count. Polling/timeout recovery remains an additional harness improvement.
